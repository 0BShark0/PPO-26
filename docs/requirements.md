# ЛР1. Требования: «Финдиректор: прибыль и деньги»

## 1. Цель

Симулятор финансового плана студии сайтов на три месяца. Главный вопрос:
**хватает ли компании денег, даже если она получает прибыль?** Пользователь меняет объём продаж,
цену, расходы и долю немедленной оплаты и сравнивает два плана.

## 2. Границы модели

Входит: одна компания, одна типовая услуга, рубли с точностью до копейки, ровно три месяца.
Продажи выполняются в своём месяце; клиент платит долю `A` сразу, остаток — в следующем месяце.
Все затраты признаются и оплачиваются в том же месяце.

Не входит: налоги, склад, амортизация, кредиты и автоматическое заимствование, порядок платежей
внутри месяца, четвёртый месяц (неоплаченная выручка месяца 3 остаётся задолженностью).

## 3. Словарь

| Термин | Определение |
| --- | --- |
| Выручка R | Стоимость выполненных за месяц услуг: `R = Q × P` (П-Б1) |
| Маржинальный доход | Выручка минус переменные расходы: `R − Q × V` (П-Б1) |
| Расходы E | `Q × V + F` (П-Б2) |
| Прибыль | `R − E`; отрицательная — убыток (П-Б2) |
| Поступления | Деньги, реально полученные от клиентов: оплата текущих продаж `S` + задолженность на начало месяца (П-Б3, П-Б4) |
| Дебиторская задолженность D | Выручка, которую клиенты ещё не оплатили: `D = R − S` (П-Б3) |
| Кассовый разрыв | Ситуация, когда прогнозные деньги на конец месяца `C < 0`. Величина нехватки `max(0, −C)` (П-Б6) |
| Потребность в финансировании | `max(0, −min(C1, C2, C3))` — сколько денег надо добавить на старте, чтобы разрыва не было (П-Б7) |

## 4. Объекты

- **План** — постоянный идентификатор, непустое название, начальные деньги (≥ 0, до копейки)
  и ровно три месяца с номерами 1, 2, 3 (П-Б10).
- **Параметры месяца** — номер, `Q` (целое ≥ 0), `P`, `V`, `F` (≥ 0, до копейки),
  `A` (целое 0–100) (П-Б8).
- **Результат (прогноз)** — для каждого месяца: выручка, маржинальный доход, расходы, прибыль,
  поступления, конечные деньги C, задолженность D; итоги: прибыль за 3 месяца, C3, D3,
  потребность в финансировании (П-Ф2, П-Б7).

## 5. Сценарии

### СЦ1. Расчёт созданного или изменённого плана (П-Ф1, П-Ф2, П-Ф5, П-Ф6)

| | |
| --- | --- |
| Ввод | Название, начальные деньги, Q/P/V/F/A для месяцев 1–3 |
| Действие | Пользователь нажимает «Рассчитать» |
| Результат | Таблица по трём месяцам и итоги П-Б7. Расчёт всегда начинается с исходных данных: деньги до месяца 1, задолженность 0 |
| Отказ | Недопустимый ввод — показываются поле и причина, прогноз не строится. После любой правки прежний результат скрывается до пересчёта |

### СЦ2. Сравнение двух планов (П-Ф3)

| | |
| --- | --- |
| Ввод | Два выбранных сохранённых плана |
| Действие | «Сравнить» |
| Результат | Рядом: прибыль за 3 месяца, C3, D3, потребность в финансировании. Исходные планы не меняются |
| Отказ | План не выбран или не найден — сообщение об ошибке, сравнение не показывается |

### СЦ3. Сохранение и открытие плана (П-Ф4, П-Ф5)

| | |
| --- | --- |
| Ввод | Данные плана; при открытии — выбор плана из списка |
| Действие | «Сохранить»; затем после перезапуска — «Открыть» |
| Результат | План появляется в списке; открытый план содержит те же значения (с копейками) и даёт тот же прогноз. Сохранение с тем же идентификатором обновляет план без дубликата |
| Отказ | Недопустимый план не сохраняется (поле и причина); несуществующий идентификатор — «План не найден» |

## 6. Приёмочные примеры

Базовые месяцы «учебного сценария» (БМ): `Q = 5, P = 30 000, V = 10 000, F = 70 000` во всех трёх месяцах.
Каждый месяц: R = 150 000, маржинальный доход = 100 000, E = 120 000, прибыль = 30 000.
Ожидания посчитаны вручную до реализации.

### ПР1. Оплата 0% (П-Б1–П-Б7)
Ввод: начальные деньги 50 000, БМ, A = 0 во всех месяцах.

| Месяц | Поступления | C | D |
| --- | ---: | ---: | ---: |
| 1 | 0 | −70 000 | 150 000 |
| 2 | 150 000 | −40 000 | 150 000 |
| 3 | 150 000 | −10 000 | 150 000 |

Итоги: прибыль 90 000; C3 = −10 000; D3 = 150 000; потребность 70 000.

### ПР2. Оплата 50% (П-Б3–П-Б5, П-Б7)
Ввод: 50 000, БМ, A = 50.

| Месяц | Поступления | C | D |
| --- | ---: | ---: | ---: |
| 1 | 75 000 | 5 000 | 75 000 |
| 2 | 150 000 | 35 000 | 75 000 |
| 3 | 150 000 | 65 000 | 75 000 |

Итоги: прибыль 90 000; C3 = 65 000; D3 = 75 000; потребность 0.

### ПР3. Оплата 100% (П-Б3, П-Б5)
Ввод: 50 000, БМ, A = 100. Поступления 150 000 каждый месяц; C = 80 000 / 110 000 / 140 000;
D = 0. Итоги: прибыль 90 000; потребность 0.

### ПР4. Отсутствие продаж (П-Б1, П-Б2, П-Б6)
Ввод: 50 000; Q = 0, P = 30 000, V = 10 000, F = 70 000, A = 100 во всех месяцах.
Каждый месяц: выручка 0, маржинальный доход 0, расходы 70 000, прибыль −70 000, поступления 0.
C = −20 000 / −90 000 / −160 000; D = 0. Итоги: прибыль −210 000; потребность 160 000.
Прогноз продолжается после отрицательного остатка (П-Б6).

### ПР5. Нулевые конечные деньги (П-Б6, П-Б7)
Ввод: 120 000, БМ, A = 0. C = 0 / 30 000 / 60 000; D = 150 000 каждый месяц.
Итоги: прибыль 90 000; потребность **0** — при C = 0 дефицита нет.

### ПР6. Недопустимый процент (П-Б8, П-Ф5)
Ввод: как ПР2, но в месяце 2 A = 101.
Ожидание: ошибка «Месяц 2, оплата сразу (A): процент оплаты должен быть целым от 0 до 100».
Прогноз не строится, план не сохраняется.

### ПР7. Сравнение и пересчёт (П-Ф3, П-Ф6)
Ввод: план «Всё через месяц» (ПР1) и «Половина сразу» (ПР2).

| Показатель | Всё через месяц | Половина сразу |
| --- | ---: | ---: |
| Прибыль за 3 месяца | 90 000 | 90 000 |
| Деньги C3 | −10 000 | 65 000 |
| Задолженность D3 | 150 000 | 75 000 |
| Потребность в финансировании | 70 000 | 0 |

Затем во втором плане A меняется на 100 и выполняется пересчёт: C3 = 140 000, D3 = 0.
До пересчёта старое сравнение скрыто. Повторный расчёт без изменений даёт те же числа.

### ПР8. Сохранение и открытие (П-Ф4, П-Б9)
Ввод: план «Копейки»: деньги 1 000,01; во всех месяцах Q = 3, P = 333,33, V = 100,10, F = 500,55, A = 33.
Расчёт месяца: R = 999,99; маржинальный доход 699,69; E = 800,85; прибыль 199,14;
S = round(329,9967) = 330,00; D = 669,99.
C = 529,16 / 728,30 / 927,44. Итоги: прибыль 597,42; D3 = 669,99; потребность 0.
Ожидание: после сохранения и открытия (в т. ч. новым экземпляром хранилища) все входы совпадают
до копейки, прогноз совпадает. Повторное сохранение с тем же идентификатором и новым названием
не меняет число планов в списке.
